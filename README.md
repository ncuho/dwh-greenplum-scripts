# Код хранилища данных Greenplum

В репозитории находятся схемы и прикладной SQL хранилища: таблицы, преобразования, функции, запросы, права и проверки. Код относится к демонстрационному экземпляру Greenplum 6.26.2 и использует синтетические данные. Исходные снимки и учётные данные в репозиторий не входят.

Код развёртывания платформы, переноса данных и целевой платформы здесь не хранится. Автоматический планировщик в репозитории не настроен: пакетная обработка представлена функциями и последовательностью их вызовов. Настоящих DAG Airflow или заданий Spark в исходном контуре этот репозиторий не подтверждает.

SQL разбит по объектам и отформатирован. Имена объектов нейтрализованы; значения строк и строковые константы, представляющие исходные данные, сохранены. Файлы переноса в другие платформы вынесены за пределы этого репозитория.

## Модель и проверенный экземпляр

Объекты разделены на исходные таблицы `ods`, существующие витрины `mart`, справочники `ref`, события `stg`, детальный слой `dds`, расчётные витрины `dm` и управление пакетами `ctl`. Индексы, функции, представления, материализованное представление, ограничения и типы включены в соответствующие каталоги.

[Полный список объектов и результаты измерений](docs/model.md) · [Описание расчётов](docs/business-logic.md) · [Проверки и их границы](docs/validation.md) · [Происхождение сборки Greenplum](docs/upstream-provenance.md).

Новые примеры в `dql/ad_hoc` подготовлены по DDL этой модели. Они не запускались на сервере и не считаются инвентаризацией реальных пользовательских запросов.

## Сборка новой пустой БД

**На действующем заполненном экземпляре эти команды запускать нельзя.** Начальный DDL и генератор не идемпотентны. Потребуются Greenplum 6.26.2, `psql`, Python 3.9+, отдельная пустая база и авторизованные снимки 46 исходных таблиц. Сами снимки и credentials здесь не публикуются; одного клонирования недостаточно.

Настройте локальный libpq service (`~/.pg_service.conf`, права 0600) на новую БД; пароли и ключи передаются штатными средствами libpq, не аргументами команд.

```bash
export PGSERVICE=og_demo
psql -X -v ON_ERROR_STOP=1 -f sources/bootstrap/01_schema.sql
python3 sources/bootstrap/load_snapshots.py /path/to/authorized-snapshots
psql -X -v ON_ERROR_STOP=1 -f sources/bootstrap/03_synthetic.sql
psql -X -v ON_ERROR_STOP=1 -f sources/bootstrap/04_logic_and_marts.sql
psql -X -v ON_ERROR_STOP=1 -f sources/bootstrap/05_batch_logic.sql
psql -X -At -v ON_ERROR_STOP=1 -f tests/sql/quality.sql > quality.jsonl
psql -X -v ON_ERROR_STOP=1 -f tests/sql/negative_gates.sql
psql -X -v ON_ERROR_STOP=1 -f tests/sql/idempotence.sql
python3 sources/bootstrap/record_validation.py /path/to/authorized-snapshots quality.jsonl
```

Порядок `\ir` в bootstrap-файлах сохраняет исходную последовательность операций: функции, представления, первый расчёт витрин, создание и refresh MV, затем пакетный пересчёт со вторым `run_id`. Тест идемпотентности повторяет второй запуск и откатывает изменения. Bootstrap не устанавливает Greenplum, сеть, сертификаты или планировщик.

После загрузки выполните `ANALYZE` таблиц и `ANALYZE ROOTPARTITION` пяти partitioned roots. [Контракт снимков](docs/source-input.md) описывает имена файлов, типы и ограничения модели.

## Проверки кода без подключения к базе

```bash
python3 -B -m unittest discover -s tests -v
```

9 тестов проходят. Characterization-проверка сопоставляет SQL-токены всех **288 извлечённых файлов** с исходным кодом после согласованной замены технических имён; SQL/PLpgSQL-логика и строковые литералы не меняются. Отдельно проверяются порядок bootstrap-включений, существование путей, состав объектов и сериализация входных значений. Эти тесты не выполняют SQL и не заменяют испытания на Greenplum.

## Существенные ограничения

- Физическая единица старых `oil_volume/gas_volume/water_volume` не установлена. Новые суточные количества остаются в `legacy units`; их нельзя подписывать тоннами или м³.
- Новые кПа/°C/мм/с/%/кВт·ч/RUB — явные синтетические единицы. Отгрузки в м³ — отдельный синтетический сценарий.
- Новые даты и наивные timestamp имеют контракт UTC. Часовой пояс оригинальных timestamp не установлен и не подменяется.
- STG сформирован генератором из DDS при начальной сборке. Постоянный поток загрузки и расписание этим кодом не создаются.
- Service→well — синтетическое соответствие, `is_causal_evidence=false`. Оно не доказывает влияние IT-инцидентов на добычу.
- Пакетные функции предназначены для фиксированного учебного пакета 2025 года. Пересекающиеся интервалы downtime отклоняются.
- Ограничения GP, PK, domain/enum и логические проверки не являются взаимозаменяемыми. Состав реальных и логических ключей указан в metadata и SQL.
