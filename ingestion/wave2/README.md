# Приём событий второй волны

Каталог содержит исходный код отдельной цепочки чтения Kafka → Iceberg staging и утилиты её ограниченной эксплуатации. Исходный приём событий в Greenplum остаётся отдельным процессом.

| Файл | Назначение |
|---|---|
| `connector.json` | Конфигурация отдельного Iceberg Sink и преобразования события; содержит привязки стенда и пути к внешним credential-файлам, но не сами файлы. |
| `target-ddl.sql`, `create-empty-target.py`, `grant-target.py` | Подготовка целевой таблицы и её прав. |
| `install-worker.sh`, `OilReadbackProbe.java` | Установка отдельного Connect worker и проверка чтения. |
| `oil-migration-fence`, `observe-fence.py` | Контроллер ограниченной границы Kafka и наблюдение за ней. |
| `enable-topic-authorizer.sh` | Административная настройка авторизации Kafka; может влиять на общие процессы. |
| `oil_kafka_ui.py`, `install-ui.sh` | Локальная панель состояния и её установка. |
| `create-test-namespace.py`, `cleanup-test-namespace.py` | Подготовка и очистка изолированного пространства для испытаний. |

Преобразование формата события находится в `../iceberg-smt-src/`, приём в GP — в `../gp-connect-src/`. Для работы нужны Kafka, Kafka Connect, совместимый Iceberg Sink и LakeKeeper, таблица staging, TLS и выданные отдельно права. Сертификаты, токены и содержимое credential-файлов в репозиторий не входят. Эти файлы содержат конкретные имена ресурсов и внутренние адреса стенда; их надо согласовать и адаптировать до использования в другой среде или публикации.

Установка worker не означает запуска коннектора, а отдельный mTLS-сертификат сам по себе не обеспечивает topic-level ACL. Вторая волна и переключение BI не следуют автоматически из наличия этого кода. Административные и очистительные операции выполняются только с проверкой их области действия и разрешений; код не является подтверждением, что они выполнялись в конкретном окружении.
