# Согласованный online-срез Greenplum

`prepare_source` сериализует исходных писателей одной короткой транзакцией, применяет до 100 READY batches и обновляет обе общие витрины. `capture` копирует согласованные relations в закрытую схему `bridge_capture`, фиксирует OID, counts и применённые exclusive offsets каждой partition. После COMMIT долгий Cedrus/Spark перенос читает эти immutable копии; Kafka producer и Connect не останавливаются.

Контракты схем/topic/reader регистрирует только администратор в `sources`. Исполнитель не может выбрать произвольные схемы. `cleanup` проверяет владельца и OID каждой копии, удаляет явно перечисленные relations без CASCADE. Исходные бизнес-таблицы не удаляются.

Применять SQL в GP 6 / PostgreSQL 9.4-совместимом окружении одной транзакцией через администратора. Исходный Airflow DAG использует тот же `prepare_source`. Capture требует свободного места под копию и кратковременно задерживает GP-записи; на промышленном объёме измерьте длительность CTAS. Это не WAL CDC и не глобальная Iceberg-транзакция.
