# Контракт авторизованных снимков

Для начальной сборки нужны46 JSON-файлов `<schema>.<table>.json` по объектам класса `exact_existing_mirror` в `metadata/asset-manifest.json`. В текущем контракте технические имена используют `og_`. Старые архивы не изменяются; для новой сборки метаданные файла должны соответствовать текущему контракту.

```json
{"table":"ods.<имя_таблицы>","snapshot_id":"<фактический_id>","columns":["<колонки_в_порядке_manifest>"],"rows":[["<значения>"]]}
```

`NULL` передаётся JSON null; даты/timestamps — строками без подмены timezone; DOUBLE — JSON number без предварительного округления. Загрузчик проверяет имя, порядок колонок, ширину строк и пустоту целевой таблицы. Все46 COPY выполняются в одной транзакции. Число Python binary64 сериализуется длинным десятичным представлением `Decimal.from_float`, предотвращающим найденное ранее отклонение в1 ULP. Табуляции, переводы строк и обратные слеши экранируются. Нефинитные числа требуют отдельного контракта и отклоняются.

Снимки фиксируются для каждой таблицы отдельно. Это не обещание общего транзакционного среза независимого внешнего источника. Авторизованный набор кейса содержит200 скважин и12 месяцев2025 года; генератор не рассчитан на произвольную входную модель.

В репозитории нет выгрузок строк, внутренних endpoint, сертификатов или ключей. Диагностика COPY не выводится автоматически, поскольку она может содержать исходное значение. Текущий loader — инструмент начального наполнения GP, не сервис переноса данных между платформами.
