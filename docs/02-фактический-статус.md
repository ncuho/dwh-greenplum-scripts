## Как обеспечивается граница

Source release и migration используют общий advisory lock Greenplum. Migration дополнительно ставит producer WRITE DENY и pause исходного sink через ограниченный SSH fence; фиксирует topic identity, exclusive offsets, checkpoints и отсутствие неприменённых партий. INITIAL сохраняет полный immutable event baseline, REFRESH использует тот же baseline плюс ограниченный raw snapshot; дырки offsets и расхождения останавливают выпуск. Это не общая ACID-транзакция нескольких Iceberg tables: публикация производится только после завершения всех сверок.

Дельта — события генератора с исправлением, повтором, удалением, late arrival и версией скважины; это не чтение WAL Greenplum. Проверяются мультимножества строк, история событий, суммы, NULL и бизнес-агрегаты. Изолированные SQL U/D/replay и Kafka→Iceberg restart/replay проверки завершились успешно.

## Права и публикация

CIAM роли `oil_dlh_reader` и `oil_dlh_engineer` сопоставлены с ролями LakeKeeper штатными API/Permissions. Reader получает SELECT только на serving tables выпуска, без доступа к raw/DDS. PUBLISH проверяет реальные grants и snapshots, переключает только dataset 8 отдельной ограниченной service identity, проверяет запрос, обновляет lineage; при ошибке поддерживается rollback. Superset RBAC и сервисная identity соединения не заменяются ролями LakeKeeper.

## Эксплуатационные границы

Это проверенный демонстрационный стенд с production-подобными механизмами, а не промышленно отказоустойчивый кластер: Kafka один broker, RF=1; автоматический DR и полноценное нагрузочное испытание не выполнялись. Выбранный и проверенный путь расчётов — Cedrus; Spark-код остаётся альтернативным проектом. CIAM сообщает v26.1.0; применены совместимые штатные инструкции 26.2.1, номер всей платформы этим не подтверждается.

API графиков проверены, но встроенный браузер не доверяет CA на переходе CIAM SSO. Для показа нужен браузер с доверенным CA платформы и авторизованным пользователем; визуальная проверка всех фильтров под этим пользователем остаётся предпросмотровым действием ведущего. Runtime patches переживают pod restart; после Helm/XaaS upgrade применяются повторно из versioned ops. Полная JSON→BI column lineage автоматической интеграцией не заявляется: зарегистрированы проверенные зависимости и column mappings таблиц, topic/BI edges имеют ограничения интерфейса каталога.
