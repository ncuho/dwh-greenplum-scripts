# Линейдж исходной цепочки добычи

Регистрирует недостающие связи исходного контура, сохраняя ранее описанный колоночный lineage. Семь служебных таблиц и hubs показаны как входы проверок `oil_gp_release`. Три hubs дополнительно связаны с реальными колонками `oil_dds.event`; физические выходы `refresh_production` связаны с исходным DAG.

Связи служебных проверок имеют описание «Операционный вход source release» и не содержат выдуманных связей колонок. История чтения и записи одной таблицы может образовывать цикл: GP применяет новую партию и проверяет получившиеся hubs в той же транзакции.

Настройка глубины исходного экрана увеличивается с двух до двенадцати уровней. В каталоге откройте отчёт «Добыча по месторождениям» Greenplum, вкладку Lineage, включите Entity Lineage и отображение pipeline как узлов. В полном графе доступны все 20 таблиц/view первой волны, Kafka, Connect, исходный DAG и функции.

Скрипт использует `OPENMETADATA_HOST` и `OPENMETADATA_JWT_TOKEN` из окружения. Он изменяет только метаданные каталога; не запускает DAG и не переносит данные.
