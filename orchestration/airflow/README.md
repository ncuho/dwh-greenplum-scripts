# Управление пакетным расчётом

`gp_daily_batch.py` — подготовленный DAG для ручного вызова существующей функции `etl.run_daily_batch`. Он не зарегистрирован и не запускался в Airflow; наличие Airflow в исходном контуре не установлено. Это отдельный вариант организации существующего SQL-процесса, не код переноса.

DAG не имеет расписания, допускает один активный запуск и не повторяет задание автоматически. Требуются Airflow с совместимым `PythonOperator`, PostgreSQL provider и настроенное отдельно подключение `greenplum_business_write`; существование подключения не утверждается. Учётную запись и её права нужно согласовать до развёртывания. Пароли в код не помещаются.

Перед ручным запуском передаются `batch_id`, `run_id`, `from_date`, `to_date`. Границы дат — начало полных месяцев, `to_date` не включается, диапазон — внутри 2025 года. Реализованная функция допускает только пакет 1. `run_id` должен соответствовать согласованной политике учёта повторов; код не выделяет его автоматически и не гарантирует глобальную уникальность. Функция изменяет исходные бизнес-таблицы и витрины. До запуска необходимо проверить данные, зависимости, длительность, блокировки, права и восстановление, а также испытать файл на отдельном экземпляре.

Копировать оба Python-файла вместе в каталог DAG Airflow. Совместимость API конкретной установленной версии Airflow и PostgreSQL provider, выдача подключения и выполнение в транзакции не подтверждены в среде Airflow. Локальные тесты `batch_parameters.py` проверяют только входы, не работу Airflow и не выполнение SQL.
