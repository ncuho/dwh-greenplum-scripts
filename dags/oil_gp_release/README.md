# Применение партий и расчёт исходных отчётов

`release()` открывает обычную транзакцию GP. `apply_ready_batches()` блокирует checkpoint на время применения READY-партий, вызывает `oil_dds.apply_batch`, затем `oil_mart.refresh_production` и `oil_mart.refresh_downtime`. Проверки rejects, журнала и аудита выполняются до COMMIT; любая ошибка откатывает весь source run. Расписание — каждую минуту после включения DAG; ручной Trigger с `{}` также доступен.

DAG не создаёт служебных копий и не вызывает миграционные SQL-функции. При переносе оператор временно приостанавливает GP connector и расписание, завершает принятые партии одним ручным run, затем удерживает стандартные SHARE-блокировки до окончания целевой загрузки и сверок. После COMMIT/ROLLBACK ingestion и расписание возобновляются с прежними offsets. Producer и независимый Iceberg sink продолжают работу.
